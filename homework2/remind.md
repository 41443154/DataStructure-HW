> 交付檔案：`Polynomial.cpp` 與 `remind.md`

## 一、題目要求與完成項目

題目以稀疏多項式（只儲存係數不為零的項）為主題。每個項目具有係數與指數：

\[
P(x)=\sum_{i=1}^{t} c_i x^{e_i}
\]

題目指定的主要類別與函式如下：

```cpp
class Term {
    friend class Polynomial;
private:
    float coef;
    int exp;
};

class Polynomial {
private:
    Term* termArray;
    int capacity;
    int terms;
public:
    Polynomial();
    Polynomial Add(Polynomial poly);
    Polynomial Mult(Polynomial poly);
    float Eval(float f);
    // 另外多載 >> 與 <<
};
```

本作業保留上述成員及三個數學運算介面，並加入安全記憶體管理、輸入正規化與操作介面。

| 功能 | 完成情形 | 說明 |
|---|---|---|
| `Polynomial()` / `Term` | ✅ | 預設建構零多項式；`Term` 儲存 `float coef` 與 `int exp` |
| `Add(Polynomial)` | ✅ | 雙指標線性合併，消除係數為零的項 |
| `Mult(Polynomial)` | ✅ | 逐項相乘後排序、合併同次項；檢查係數與指數溢位 |
| `Eval(float)` | ✅ | 稀疏 Horner 法，使用較高精度的中間結果 |
| `operator>>` / `operator<<` | ✅ | 一行輸入一個多項式；輸出整理後的標準表示式 |
| 動態陣列擴容 | ✅ | `capacity` 不足時成倍擴容 |
| 複製、移動與解構 | ✅ | 深複製、copy-and-swap、移動建構、釋放陣列 |
| 亂序與同次項 | ✅ | 自動排序、加總重複次方、消去零項 |
| 輸入防護 | ✅ | 項數、指數、非有限係數、多餘資料與欄位不足檢查 |
| 互動操作 | ✅ | 顯示、加法、乘法、A/B 代入、重新輸入、顯示統計 |
| 檔案讀寫 | ✅ | 可儲存 A、B；讀入前全部檢查，失敗時不覆寫舊資料 |
| 自動測試與效能 | ✅ | 20 項測試檢查、其中一項含 100 組隨機交叉驗證；獨立 benchmark |

**輸入格式的選擇：**三份參考程式採用「項數，接著是（係數、指數）配對」，因此本版沿用此順序，並要求每筆多項式在**同一行**輸入完成。原始題目圖片中若另有指定輸入順序或精度，以老師的正式規格為準；本報告沒有把參考作者自行增加的「固定兩位小數」當成題目限制。

### 2.3 資料不變量

任何已成功建立的多項式，一律維持：

1. `0 <= terms <= capacity`。
2. `termArray` 中只保留非零項；零多項式以 `terms == 0` 表示。
3. 指數皆為非負整數，並依由大到小排列。
4. 相同指數只會出現一次。
5. 每個物件擁有自己的動態陣列；複製後可獨立修改。

維持此規則的好處是：`Add()` 不需要每次重新排序，`<<` 也不會印出同次項重複或多餘的 `0x^n`。

## 三、重要資料結構與演算法

### 3.1 動態陣列與記憶體安全

- **建構子：**起始為 `nullptr`、容量 0、項數 0，代表零多項式。
- **擴容 `reserve()`：**空間不足時以倍增方式配置新 `Term[]`，先複製有效元素，再釋放舊陣列。
- **複製建構子：**另開記憶體並複製項目，避免淺複製。
- **賦值運算子：**使用 copy-and-swap，先準備完整新物件；複製失敗不會修改原物件。
- **移動建構子：**接手暫存物件的陣列並清空來源，減少不必要的複製。
- **解構函式：**使用 `delete[] termArray`，避免記憶體洩漏。

同時，乘法與輸入解析的暫存陣列使用 `unique_ptr<T[]>` 管理。這不是取代題目要求的主儲存方式，而是避免處理失敗時遺漏釋放暫存記憶體。

### 3.2 輸入解析、排序、同次項合併

輸入一行：

```text
5 1 0 4 3 -2 1 5 3 2 1
```

表示 `1 + 4x^3 - 2x + 5x^3 + 2x`。整理後為：

```text
9x^3 + 1
```

實作步驟：

1. 讀取「項數」及相應的係數、指數；檢查資料格式與範圍。
2. 將項目依指數由大到小排序，時間 `O(t log t)`。
3. 逐段合併相同指數的係數，先用 `long double` 暫存加總。
4. 轉成題目規定的 `float`，移除相消或變成零的項。
5. 只有完成全部檢查才接受結果，避免輸入失敗時污染 A 或 B。

本版不會自動截斷至兩位小數，而是接受 `float` 可表示的有限數值；標準輸出會使用能往返解析的精簡數字格式。

### 3.3 多項式加法 `Add()`

兩個多項式已經按指數遞減排列，所以用兩個索引比較目前指數：

```text
while A 和 B 都還有項目：
    若 A 的指數較大：加入 A 的目前項目，A 往後
    若 B 的指數較大：加入 B 的目前項目，B 往後
    若兩者指數相同：係數相加，非零才加入，兩邊都往後
最後加入尚未掃描完的項目
```

例如：

\[
A(x)=3x^2+2x+1,\quad B(x)=x-1
\]

\[
\boxed{A(x)+B(x)=3x^2+3x}
\]

### 3.4 多項式乘法 `Mult()`

乘法仍依據分配律，將 A 的每項與 B 的每項配對：

\[
(c_ix^{e_i})(d_jx^{f_j})=(c_id_j)x^{e_i+f_j}
\]

與第一份「每得到一個單項就重新做整個 `Add()`」、第二份「每列建立暫存多項式再相加」不同，本版**先形成乘積項目陣列、排序，最後只合併一次**。這與第三位「先整理、後合併」的思路相近，但使用老師要求的 `float`/`int` 型別，並且只建立一個題目規格的 `Polynomial` 類別。

- 係數乘法與同次項加總的中間型別為 `long double`。
- 指數加法先用 `long long` 計算；超過 `INT_MAX` 就回報錯誤。
- 合併後的係數若超過 `float` 範圍，也回報錯誤，不輸出無意義的 `inf`。

例：

\[
(3x^2+2x+1)(x-1)=\boxed{3x^3-x^2-x-1}
\]

### 3.5 多項式代入 `Eval()`

一般定義為：

\[
P(f)=\sum_i c_i f^{e_i}
\]

本版利用指數降序的特性，使用**稀疏 Horner 法**：相鄰兩項只需要處理指數差距，最後再乘上最低指數對應的次方。運算過程使用 `long double`，回傳時仍符合題目規定的 `float Eval(float f)`。

例如：

\[
A(2)=3(2)^2+2(2)+1=\boxed{17}
\]

> 說明：「代入運算內部使用 `pow()`」並不是增加新的「多項式快速冪」選單功能。此版本沒有提供微分、積分、除法或多項式冪次運算。

### 3.6 輸出格式

根據一般多項式書寫習慣：

| 原始項目 | 螢幕顯示 |
|---|---|
| `1x^5` | `x^5` |
| `-1x^1` | `-x` |
| `3x^1` | `3x` |
| `-2x^0` | `-2` |
| 所有項目相消 | `0` |
| 正負號混合 | `3x^3 - 2x + 1` |

一般畫面輸出是給人閱讀的形式；`Save()` 另外輸出「項數 係數 指數 ...」的格式，以便程式重新載入。**顯示格式與存檔格式分開**，避免把 `3x^2 + 2x + 1` 直接寫進檔案後無法用 `operator>>` 讀回。

## 五、時間與空間複雜度

設 A 與 B 各自含 `m`、`n` 個非零項；`k = mn` 為尚未合併的乘積項數。

| 操作 | 時間複雜度 | 額外空間／說明 |
|---|---|---|
| 動態陣列擴容 | 單次 `O(t)` | `O(t)` 新陣列；倍增下連續附加的攤銷成本為每項 `O(1)` |
| 解析與正規化 t 項 | `O(t log t)` | `O(t)` 暫存和主陣列 |
| `Add()` | `O(m+n)` | `O(m+n)` 回傳結果；由值傳遞 B 的複製仍為線性 |
| `Mult()` | `O(k log k)`（`k = mn`） | `O(k)` 乘積暫存，另有排序實作的堆疊空間 |
| `Eval()` | 對 t 個非零項呼叫 `O(t)` 次 `pow()` | `O(1)` 額外資料；總時間仍受到 `pow()` 實作和指數大小影響 |
| 複製建構 | `O(t)` | `O(t)` |
| 輸出 | `O(t)` 次項目處理 | 建立文字結果需與輸出字數成正比的空間 |

多項式乘法不可只寫 `O(mn)`：程式會**先排序 `mn` 個乘積項**，因此完整主要步驟的界限為 `O(mn log(mn))`。輸入與輸出格式化、浮點數函式庫的成本另外計算。

主資料的 `Term` 陣列容量以倍增方式配置，未使用的保留容量不算在 `terms` 中；顯示統計時可以比較實際非零項與配置容量。

## 七、效能實測

### 7.1 方法

- 使用 `std::chrono::steady_clock` 測量運算本身，不把輸入提示與檔案讀寫算進時間。
- A、B 各有 n 個非零項；指數範圍從 `0` 到 `n-1`，所有係數均為 1。
- 每個 n 的加法執行 200 次取平均；乘法執行 3 次取平均。
- 乘積未合併前有 `n²` 項，合併後有 `2n-1` 個非零項。
- 測試環境：本次執行容器的 **x86_64、GCC 14.2.0、`-O2`、C++17**，時間為毫秒（ms）。

### 7.2 實際結果

以下採用本次重複執行中的其中一組紀錄；不同負載與機器可能有差異。

| A、B 各 n 項 | 加法平均時間（200 次） | 乘法平均時間（3 次） | 乘積非零項數 |
|---:|---:|---:|---:|
| 100 | 0.000866 ms | 0.410073 ms | 199 |
| 200 | 0.002258 ms | 1.785015 ms | 399 |
| 400 | 0.005274 ms | 7.779835 ms | 799 |

### 7.3 分析

當 n 增加時，加法主要增加的是線性走訪與回傳結果的工作量；乘法則需要產生 `n²` 個暫存乘積並排序，時間上升更明顯。這與前述複雜度趨勢一致。由於每筆測試耗時很短，加法量測尤其容易受到排程與快取影響，因此上述數據主要用於**觀察趨勢**，不應視為不同電腦間的絕對效能排名。

本次未在相同環境與相同輸入下直接對三份參考作品進行對照量測，因此不能據此聲稱本版一定比三位作者的程式快。

## 八、遭遇的問題、設計取捨與心得

**問題一：動態指標的淺複製風險。** 只宣告 `Term*` 而沒有妥善實作複製及解構，可能導致多個物件共用一塊陣列、重複釋放或記憶體洩漏。本版以完整複製與移動生命週期處理，並對自我賦值和物件獨立性設計測試。

**問題二：輸入不保證排序或唯一。** 如果假設每個指數都只出現一次，或假設資料必定按降序輸入，加法雙指標的前提就會被破壞。本版在輸入時集中進行排序、同次項合併、刪零，讓其他函式能依靠相同不變量。

**問題三：運算正確性與浮點數表示。** 由於老師指定 `float` 係數與 `float Eval(float)`，本版不能宣稱具備第三份大整數程式的任意精度。使用 `long double` 做中間計算並檢查溢位，能降低部分誤差，但**無法消除 float 本身的有限精度與極端情況下的消去誤差**。輸入係數仍以 float 儲存，不支援無限位數的大數。

**問題四：功能多不等於加上無關的數學操作。** 這份作業的數學核心仍是加法、乘法、代入。提升完整度的方法是：輸入檢查、錯誤後重試、可讀的輸出、資料存取、安全複製、邊界測試和效能分析。這些功能更能直接展示對題目本身的掌握。

**問題五：保留老師規格與改善效能的平衡。** 主儲存仍使用 `Term*`、`capacity`、`terms`；乘法運算中只使用一個受管理的暫存陣列來排序乘積，沒有將主資料結構改成 `std::map` 或 `std::vector`。因此可以兼顧題目要求與相對清楚的程式碼。

### 已知限制

1. 本版只允許非負整數指數，遵守一般多項式的定義；不支援負次方表示的 Laurent 多項式。
2. 係數與回傳結果受 `float` 精度及範圍限制；超出可表示範圍會回報錯誤，而不是自動擴充成大整數。
3. `Mult()` 需要存放 `m×n` 個乘積暫存項，大型輸入可能耗用大量記憶體。
4. 互動模式中，每個多項式的所有資料需輸入於同一行；若老師評測要求跨行輸入，需再調整讀入規則。
5. 效能數據是單次環境紀錄，並非普遍的效能保證。
