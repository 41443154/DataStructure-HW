## 1. 作業內容與設計目標
多項式由許多「係數 × x 的次方」組成，例如：

```text
P(x) = 3x^2 + 2x + 1
```

可以拆成三個項目：

| 係數（coef） | 指數（exp） | 代表的項目 |
|---:|---:|---|
| 3 | 2 | `3x^2` |
| 2 | 1 | `2x` |
| 1 | 0 | `1` |

程式只儲存**係數不為 0 的項目**，因此稱為「稀疏多項式」。這樣不需要為不存在的次方浪費陣列空間。

依題目指定的結構，主要使用以下類別和資料成員：

```cpp
class Term {
    friend class Polynomial;
private:
    float coef;  // 係數
    int exp;     // 指數
};

class Polynomial {
private:
    Term* termArray;  // 儲存多項式項目的動態陣列
    int capacity;     // 陣列目前容量
    int terms;        // 實際非零項數量
public:
    Polynomial();
    Polynomial Add(Polynomial poly);
    Polynomial Mult(Polynomial poly);
    float Eval(float f);
    // 另外實作 >> 與 << 運算子多載
};
```

**核心功能完成情形**：

| 功能 | 說明 |
|---|---|
| 多項式加法 `Add()` | 相同次方的係數相加，自動刪掉結果為 0 的項 |
| 多項式乘法 `Mult()` | 每項互相相乘，再整理相同次方 |
| 代入計算 `Eval()` | 輸入 x，求出多項式的值 |
| 輸入與輸出 `>>`、`<<` | 輸入多項式，並以易讀的數學格式輸出 |
| 動態陣列 | 項目增多時自動擴充容量 |
| 輸入自動整理 | 支援亂序、重複次方、零係數 |
| 記憶體安全 | 正確複製、移動與釋放陣列 |
| 互動選單 | 可重複操作，不需要每做一次就重新執行程式 |
| 檔案讀寫 | 可將 A、B 儲存到檔案，之後再載入 |
| 自動測試 | 包含基本案例、錯誤輸入、記憶體相關案例與隨機驗證 |

## 2. 執行與使用說明
### 輸入格式

**一個多項式輸入一行**，順序為：

```text
項數  係數1 指數1  係數2 指數2  ...
```

假設要輸入：

```text
A(x) = 3x^2 + 2x + 1
B(x) = x - 1
```

在程式中依序輸入：

```text
3 3 2 2 1 1 0
2 1 1 -1 0
```

第一行的第一個 `3` 表示 A 有三項，後面依序是 `(3,2)`、`(2,1)`、`(1,0)`，即「係數、指數」配對。

- `0` 表示零多項式。
- 指數只能是非負整數，例如 `0`、`1`、`2`。
- 係數可以是整數、小數或科學記號，例如 `-2.5`、`1.5e-2`。
- 輸入項目的順序可以打亂，也可以有重複次方；程式會整理。
- 項數和輸入資料必須吻合，不能少輸或多輸。
- 一個多項式最多接受 **200000 個輸入項目**，避免不合理輸入耗盡記憶體。

### 操作選單

程式啟動時會先要求輸入 A 和 B，之後顯示選單：

| 輸入數字 | 功能 |
|---:|---|
| 1 | 顯示 A、B |
| 2 | 計算 A + B |
| 3 | 計算 A × B |
| 4 | 代入 x，計算 A(x) |
| 5 | 代入 x，計算 B(x) |
| 6 | 重新輸入 A |
| 7 | 重新輸入 B |
| 8 | 儲存 A、B 到檔案 |
| 9 | 從檔案讀取 A、B |
| 10 | 顯示項數、最高次方、陣列容量 |
| 11 | 執行自動正確性測試 |
| 12 | 執行大量資料壓力測試 |
| 0 | 結束程式 |

### 一次執行的範例

如果不想使用選單，也可以用 `--batch` 一次完成基本運算。程式依序讀取 **A、B、x**，各佔一行。

輸入：

```text
3 3 2 2 1 1 0
2 1 1 -1 0
2
```

輸出：

```text
A = 3x^2 + 2x + 1
B = x - 1
A + B = 3x^2 + 3x
A * B = 3x^3 - x^2 - x - 1
A(2) = 17
B(2) = 1
```

執行方式：

```bash
./Polynomial --batch
```

Windows 則改成 `Polynomial.exe --batch`。

## 3. 程式設計說明

### 3.1 `Term` 與 `Polynomial` 如何合作？

- `Term`：只負責存一項的係數、指數。
- `Polynomial`：負責管理許多 `Term`，並提供輸入、顯示、加法、乘法、代入等操作。
- `termArray`：指向存放 `Term` 的陣列。
- `terms`：真正使用的項目數。
- `capacity`：已經準備好的陣列空間大小，不一定等於 `terms`。

例如陣列容量為 8，但只有 3 個非零項，此時 `capacity = 8`、`terms = 3`。剩下的 5 格是預留空間。

程式始終保持以下規則：

1. 只保留係數非零的項目。
2. 指數由大到小排列。
3. 相同指數只保留一項（先把係數合併）。
4. 每個 `Polynomial` 物件擁有自己的陣列，不會不小心共用記憶體。

如此一來，加法和輸出都能直接使用已整理好的資料。

### 3.2 動態陣列與記憶體管理

在設計動態陣列時，我希望兼顧空間利用率與物件複製的安全性，因此將容量管理、深複製及記憶體釋放分開處理。

- **建構子**：預設為零多項式，`termArray = nullptr`、`terms = 0`、`capacity = 0`。
- **擴容 `reserve()`**：空間不夠時，建立更大的陣列，複製原本有效的項目，最後釋放舊陣列；容量一般以倍增方式成長。
- **複製建構子**：複製多項式時，另外建立一塊陣列。修改原本的 A，不會影響複製品。
- **賦值運算子**：使用 *copy-and-swap*（先準備副本，再交換內容），避免複製失敗時破壞舊資料。
- **移動建構子**：若有可直接接手的暫存陣列，就避免再複製一次。
- **解構函式**：使用 `delete[] termArray` 釋放記憶體。

乘法和輸入解析時使用自行實作的 `ScopedArray` 管理**暫存空間**，確保發生錯誤時也能自動釋放；這樣可以遵守老師禁止額外標頭的限制。主資料結構仍是題目指定的 `Term*` 動態陣列。

### 3.3 輸入後自動排序、合併同次項

例如使用者輸入：

```text
5 1 0 4 3 -2 1 5 3 2 1
```

代表：

```text
1 + 4x^3 - 2x + 5x^3 + 2x
```

整理過程：

```text
4x^3 + 5x^3 - 2x + 2x + 1
= 9x^3 + 1
```

程式會先按指數排序，再將相同次方合併；如果合併後係數為 0，該項就刪除。

**這樣設計的原因**：使用者不需要先手動整理多項式，也不會因為輸入順序不同就造成加法錯誤。

### 3.4 多項式加法 `Add()`

加法使用兩個位置索引，從 A 和 B 的最高次方開始比較：

1. A 的次方比較大，就先把 A 這項放進答案。
2. B 的次方比較大，就先把 B 這項放進答案。
3. 次方相同，就把係數加起來；如果結果是 0，直接略過。
4. 其中一邊走完後，把另一邊剩下的項目接到答案後面。

範例：

```text
A(x) = 3x^2 + 2x + 1
B(x) = x - 1
------------------
A+B  = 3x^2 + 3x
```

我選擇使用兩個索引進行加法，並先確保輸入已經排序與合併。這樣既能維持線性掃描的效率，也能正確處理亂序輸入。

### 3.5 多項式乘法 `Mult()`

乘法的基本原理是：**每一項都要和另一個多項式的每一項相乘**。

例如：

```text
(2x^2) * (3x) = 6x^3
```

係數相乘：`2 * 3 = 6`。指數相加：`2 + 1 = 3`。

完整範例：

```text
(3x^2 + 2x + 1) * (x - 1)
= 3x^3 - 3x^2 + 2x^2 - 2x + x - 1
= 3x^3 - x^2 - x - 1
```

程式做法是**先產生所有乘積項目，接著排序，最後一次合併同次項**。這樣不用每算出一項就重新執行整個多項式加法。

另外，程式會檢查乘法結果的指數是否超出 `int` 範圍、係數是否超出 `float` 可表示的範圍，避免輸出錯誤的無限大數值。

### 3.6 代入計算 `Eval()`

代入的意思，是把多項式中的 `x` 換成指定數字。

例如：

```text
A(x) = 3x^2 + 2x + 1
x = 2

A(2) = 3*(2^2) + 2*2 + 1
     = 12 + 4 + 1
     = 17
```

程式內部採用「稀疏 Horner 法」整理計算步驟，減少不必要的重複計算，並使用 `long double` 保存中間結果，以降低部分浮點誤差。**函式回傳型別仍然是題目要求的 `float`**。

> 這裡為了算出 x 的次方而使用 `pow()`，並不代表新增了「多項式快速冪」功能。

### 3.7 輸出格式與檔案格式

顯示時，程式會把多項式整理成容易閱讀的樣子：

| 原始資料代表 | 顯示結果 |
|---|---|
| `1x^5` | `x^5` |
| `-1x^1` | `-x` |
| `3x^1` | `3x` |
| `-2x^0` | `-2` |
| 所有項目互相抵消 | `0` |

但存檔時必須保存可重新讀入的資料，所以使用原本的「項數、係數、指數」格式。例如存檔內容是：

```text
3 3 2 2 1 1 0
2 1 1 -1 0
```

這兩行分別代表 A、B。載入檔案時會先檢查資料是否正確；若檔案內容有誤，**不會覆蓋原本的 A、B**。

## 4. 我的設計思路

我希望這份程式不只算得出答案，也能處理不同的輸入情況，讓每個功能之間維持一致的資料格式

| 設計時考慮的問題 | 我的處理方式 | 達成的效果 |
|---|---|---|
| 輸入項目可能順序混亂或重複 | 讀入後先排序、合併同次項，並移除零係數 | 加法、乘法和顯示都能使用一致的資料 |
| 多項式的項數不固定 | 使用 `Term*` 動態陣列，容量不足時擴充 | 不需要預先固定所有項目的數量 |
| 物件複製可能造成共用指標 | 實作深複製、賦值運算子和解構函式 | 避免資料互相影響與重複釋放 |
| 輸入錯誤可能破壞原本資料 | 先檢查新資料，確認有效才更新物件 | 使用者輸入錯誤時仍能保留原資料 |
| 程式需要容易操作及驗證 | 加入操作選單、檔案讀寫與自動測試 | 方便連續操作，也能檢查結果是否正確 |

## 5. 效率分析

以下的 `m`、`n` 分別代表 A、B 的非零項數量。

| 操作 | 大致時間複雜度 | 說明 |
|---|---|---|
| 輸入排序與整理 | `O(t log t)` | 輸入 t 項，先排序再合併 |
| 加法 | `O(m + n)` | 兩個多項式各掃描一次 |
| 乘法 | `O(mn log(mn))` | 先產生 m×n 個乘積項，再排序合併 |
| 複製多項式 | `O(t)` | 把每個有效項目複製一遍 |
| 動態陣列連續新增項目 | 攤銷每項 `O(1)` | 容量倍增，可減少反覆重新配置 |
| 代入計算 | 走訪 `t` 項，另需計算次方 | 實際耗時與次方計算也有關 |

`O(...)` 表示資料量變大時，運算所需工作量大致如何增加；不代表執行一定需要固定幾秒。

乘法需要暫存最多 `m × n` 個乘積項目，因此輸入非常大時，可能需要較多記憶體。

## 7. 遇到的問題與改善方式

**問題一：有指標就需要注意記憶體。**
如果直接複製 `Term*` 指標，兩個物件可能指向同一塊陣列，
最後造成重複釋放或互相修改，我讓每個多項式各自管理資料

**問題二：使用者不一定會照次方順序輸入。**
單純的雙指標加法要求資料已排序。所以我先在輸入時完成排序與合併，讓後續的加法、輸出都不必再擔心重複指數。

**問題三：小數運算可能有誤差。**
老師規格中的係數是 `float`，因此仍有精度限制。我使用 `long double` 做部分中間計算，並檢查明顯溢位，不是任意精度計算器，也不能保證完全沒有浮點誤差

### 已知限制

1. 指數只接受非負整數，不支援負次方。
2. 係數及代入結果受 `float` 的數值範圍和精度限制。
3. 每筆輸入的所有項目要在同一行；不接受一筆多項式跨多行輸入。
4. 乘法需要暫存所有配對乘積，項數很大時可能需要較多記憶體。
5. 輸入格式採用「項數、係數、指數」的形式；如果老師正式題目另有指定，應以老師的規格為準。
